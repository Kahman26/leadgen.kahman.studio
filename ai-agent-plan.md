# План: ИИ-агент продажника Kahman Studio

## Что агент делает

1. **Предлагает ответ клиенту** с учётом всей переписки: на каком этапе клиент, что он сейчас сказал, какой следующий шаг. Даёт 2–3 варианта текста.
2. **Собирает индивидуальное КП** по брифу и аудиту сайта клиента: подбирает модули и пишет тексты под его проблемы. Сумму считает код по прайсу, модель её не придумывает.

Агент работает как помощник: пишет черновик, отправляет человек. Автоответы без проверки можно включить позже и только для входящих заявок на простые вопросы.

Источники знаний, по убыванию приоритета:
- **твои документы**: прайс, сметы, скрипт продаж, инструкция по переписке, ниша бань. Это факты и сам оффер;
- **канал продажника**: методика, то есть как строить сообщение, работать с возражениями и дожимать;
- **реальные переписки** с клиентами, твои и продажника, с пометкой, чем закончилось. Это лучшие примеры для модели.

## Этап 1. Инвентаризация 10 ГБ (полдня)

Делается на ПК: экспорт лежит там, и Gemini работает оттуда через прокси.
- Скрипт считает файлы по типам, суммарную длительность видео и аудио через ffprobe, дубли по хэшу (одно видео часто постят дважды) и проверяет, валиден ли `result.json`.
- Стоит посмотреть, что успел сделать Codex по старому промпту (`processed.jsonl`): он инкрементальный, повторно ничего обрабатывать не придётся.
- Ориентир: из 10 ГБ после расшифровки обычно остаётся 5–30 МБ текста. Почти весь объём занимает видео.

## Этап 2. Медиа в текст (1–3 дня, в основном это ожидание квот)

- **Видео и кружки**: вырезаем только звук в mp3 (10 ГБ сжимаются примерно до 1 ГБ) и расшифровываем через Gemini Flash. Если речи нет, берём 1 кадр раз в 2–3 секунды и делаем OCR слайдов.
- **Фото**: сначала классификация «полезное / мусор». Мемы, обложки и селфи отбрасываем, у полезного распознаём весь текст.
- **PDF**: текстовый слой через pypdf, сканы через Gemini.
- **Ссылки**: статьи скачиваем, YouTube собираем в список.
- Если бесплатной квоты Gemini не хватит: платный Gemini Flash за такой объём стоит единицы долларов. Другой вариант — Yandex SpeechKit: он работает с сервера и оплачивается в рублях.

На выходе получаются **материалы**: один пост вместе с расшифровками его медиа = один файл `.md` с датой и ссылкой.

## Этап 3. Выжимка знаний (DeepSeek, около дня)

**Map.** Каждый материал отправляем в `deepseek-flash`, ответ в JSON. Схему из промпта Codex (`docs/codex-prompt-tg-export.md`) нужно расширить под новые задачи:
- `stage`: первое касание / квалификация / бриф / оффер / цена / возражение / дожим / закрытие / после продажи;
- `kp`: как он строит КП, обосновывает цену, упаковывает пакеты;
- `inbound`: как отвечать на входящие вопросы вроде «сколько стоит сайт?»;
- `dialog_examples`: переписки из его разборов дословно;
- плюс уже существующие поля `principles / techniques / phrases / objections / mistakes / relevance`.

**Reduce.** Тема за темой, через `deepseek-v4-pro`: сливаем выжимки, убираем повторы, выбрасываем нерелевантное (найм, управление отделом, мотивация).

**Твоя вычитка** обязательна: 1–2 вечера. Это самый важный этап. Без неё агент будет повторять всё подряд, в том числе то, с чем ты не согласен.

## Этап 4. База знаний

```
knowledge/
  core/       rules.md, tone.md, dont.md        — всегда в промпте
  stages/     first_touch, qualification, brief, offer,
              price, objections, followups, closing   — по этапу
  offer/      prices.yaml   — прайс структурой, модель его не переписывает
              packages.md, cases.md (из completed-projects), faq.md
  niche/      bani_sauny.md, oteli_bazy.md
  kp/         structure.md, template.docx
  examples/   dialogs.jsonl — ситуация → ответ → результат
```

Для поиска по сырой выжимке, когда нужна редкая ситуация, хватит SQLite FTS5 прямо в leadgen. У DeepSeek нет API эмбеддингов, а векторная база на старте не нужна.

## Этап 5. Агент в leadgen (сервер, 1–2 недели)

На каждый запрос «предложи ответ»:
1. **Разбор** (JSON): этап воронки, намерение клиента, тип возражения, чего не хватает для КП.
2. **Подбор контекста**: core + файл этапа + ниша + 3–5 похожих примеров из `dialogs.jsonl`.
3. **Генерация**: 2–3 варианта ответа и подсказка «следующий шаг / что спросить».
4. **Инструменты** (function calling, DeepSeek его поддерживает): `get_price(пакет, опции)`, `get_case(ниша)`, `get_audit(lead_id)`, `make_kp(...)`.
5. **Проверка кодом**: длина, нет цен вне прайса, нет ссылок в холодных сообщениях, нет запрещённых слов. Если проверка не пройдена, генерируем заново.
6. **152-ФЗ**: перед отправкой в DeepSeek имена, телефоны и почты заменяются метками `{CLIENT_NAME}`, после генерации код подставляет их обратно.
7. **Лог** каждой генерации: что предложено, что реально отправили, чем закончилось.

Постоянная часть промпта (core + правила) всегда идёт первой, тогда DeepSeek берёт её из кэша по низкой цене.

## Этап 6. Генератор КП (около недели, параллельно с этапом 5)

- На входе бриф (5 вопросов из `docs/instrukciya-prodazhi-v-perepiske.md`), аудит сайта и ниша.
- Модель выбирает модули из `prices.yaml` и пишет персональные блоки: «что теряете сейчас» по находкам аудита, «что сделаем», подходящие кейсы.
- Код считает смету, сроки и этапы оплаты и собирает docx по шаблону смет из `docs/estimate`, затем PDF.
- Перед отправкой КП проверяет человек.

## Этап 7. Оценка качества (до запуска и потом постоянно)

- Тестовый набор: 30 реальных ситуаций из переписок («дорого», «скиньте прайс», молчание после макета, «сайт делает племянник»…).
- После каждой правки базы прогоняем набор и сравниваем вслепую с прошлой версией. В помощь можно добавить LLM-судью с оценкой по правилам из `rules.md`.
- Метрики в работе: доля черновиков, отправленных без правок, доля ответивших клиентов, конверсия в созвон и КП.

## Этап 8. Интеграции, по порядку

1. **Интерфейс leadgen**: в карточке лида кнопки «Предложить ответ» и «Сделать КП». Самое простое, и с этого стоит начать.
2. **Telegram-бот-помощник для продажника.** Продажник пересылает боту сообщение клиента и получает варианты с кнопками «Скопировать», «Другой вариант», «Короче», «Сделать КП». Риска бана нет: пишет живой человек со своего аккаунта.
3. **Telegram Business (подключённый бот).** Бот видит входящие в рабочем аккаунте и кладёт черновик продажнику на одобрение. Позже можно включить автоответ в нерабочее время на типовые вопросы. Нужен Telegram Premium на рабочем аккаунте.
4. **MAX** (у VK есть Bot API). Подключать, если клиенты пишут туда. Перед стартом нужно проверить актуальные условия для ботов организаций.
5. **WhatsApp**: только через бота-помощника, то есть скопировал и вставил. Официальный Cloud API требует бизнес-аккаунт Meta, а неофициальные библиотеки приводят к бану номера.
6. **Почта и форма на сайте**: входящая заявка сразу получает черновик ответа в Telegram.

Автоматическую отправку холодных сообщений агентом не делаем: это бан номеров и риск по 38-ФЗ.

## Этап 9. Цикл улучшения

- В боте и в leadgen отмечаешь исход: «ответил», «созвон», «КП», «оплата», «слился».
- Удачные диалоги автоматически попадают в `examples/dialogs.jsonl`.
- Раз в 2 недели смотришь неудачные генерации и правишь `rules.md`.

## Юридически

- Контент продажника используем только внутри компании. Базу не публикуем, «от его имени» не пишем.
- Персональные данные клиентов в DeepSeek не отправляем, они маскируются (этап 5, п. 6).
- Переписки продажника для примеров берём с его согласия, это оговаривается в договоре ГПХ.

## С чего начать

1. Узнать, сколько Codex уже обработал (`ChatExport_..._extracted/processed.jsonl` на ПК) и как выглядят расшифровки.
2. Собрать 20–30 реальных переписок с клиентами, своих и продажника, с исходом. Из всего материала это самое ценное, ценнее канала.
3. Перевести прайс из `docs/estimate/Прайс — бани и сауны.docx` в `prices.yaml`.

Медиа обрабатываются на ПК. На сервер загружается только готовый текст из `_extracted` (десятки мегабайт), дальше выжимка, база знаний и агент собираются прямо в leadgen.
